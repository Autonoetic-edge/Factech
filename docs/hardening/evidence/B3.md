## 1. What is frozen

Name: **`pad-sequence-v3-guided`**. Selected only by the exact environment value
`HEAD_GATE_POLICY=pad-sequence-v3-guided`; every other value, including empty,
selects the frozen `pad-sequence-v2-slow`.

Definition of record: `engine/app/head_sequence.py`, the block below the
`# --- Development-only policy version.` marker — `selected_policy()`,
`validate_for()`, `validate_guided()` and the constants beside them. That block
is the definition; this file records its identity, not a second copy of it.

The candidate differs from `pad-sequence-v2-slow` in exactly two decision rules
(full reasoning in [B2](B2.md) §2):

1. **Stillness is judged per frame against the median baseline.** At least
   `SETTLE_INLIERS_MIN = 2` settle frames must sit within `STILL_TOLERANCE = 0.15`
   of the median, instead of the whole settle window having to fit inside that
   span. The `|baseline| <= 0.25` frontality check is unchanged.
2. **A late switch is tolerated only as a leading run.** Frames showing the
   previous turn are ignored inside a window only if they precede that window's
   first valid frame. An opposite frame at or after the first valid frame still
   fails `opposite_action_in_window`.

Plus one output-only addition: the v3 result carries `policy`, `settle_inliers`
and a coarse `hint` (`hold_still`, `turn_sooner`, `turn_less_or_more`,
`try_again`, or `None` on success) that carries no score, threshold, yaw value or
PAD detail. The hint reaches nothing outside the engine's own decision dict;
`engine/app/main.py` is not approved and is untouched.

## 4. What the freeze means from here

- Any change to any file in §2, or to any constant in §1, **creates a new policy
  version** and restarts held-out evaluation. It does not amend
  `pad-sequence-v3-guided`.
- The drift guard is `tools/hardening_verify_baseline.py` against
  `source-sha256.v4.json` for the six engine files and the models, plus the four
  harness hashes in §2, which must be checked by hand until a row puts them in a
  manifest.
- The evaluation protocol for B4 (held-out recognition) and B5 (physical PAD and
  injection) is **locked as written in `docs/hardening/BIOMETRIC_TRACK.md`**
  sections B4 and B5, as of this date. Those sections are the pre-registered
  protocol; they were written before any held-out data exists and are not to be
  edited to fit a result.
- **B4 and B5 are not started and are not planned here.** B4 needs recordings
  from participants who were not among the first nine, and where that round runs
  is the user's decision, outstanding. Nothing in this phase touches the VPS.

## 7. New proposed row — the head gate stamps no version anywhere

Proposed, **not approved and not applied.** Raised from B2 §10.1, narrowed on the
user's instruction: `engine/app/anti_spoof.py` is **not** to be touched, and
`pad.policy` is **not** to be renamed or made a compound string. `pad.policy` is
honestly named for what it stamps — the PAD policy — and it is correct today.

The real gap is that the head gate's own version is recorded nowhere at all. A
decision trace shows `pad.policy = "pad-sequence-v2-slow"` and a
`head_sequence` block with no version in it, so which head-gate version judged a
capture is not recoverable from the record. Under B4/B5 that is a data-integrity
problem, because results are grouped by policy string.

Row as proposed into the plan's table:

> **`engine/app/head_sequence.py` (second row)** — in the appended development
> block only, make `validate_for()` stamp the head gate's own policy name into the
> result it returns for BOTH policies, so a decision record says which head-gate
> version judged it. One field, `policy`, one of the two existing name constants.
> No scoring change, no threshold, no wire-format change, and `validate()` itself
> is not edited.

One line, in the v2 branch of `validate_for()` — the frozen `validate()` is not
entered. `validate_guided()` already sets this field, so the effect is that
`policy` becomes always present instead of present only on v3.

Two consequences the reviewer should weigh before approving:

- The `head_sequence` block in a v2-slow decision record gains one string key.
  That is a decision-trace output change on the default path, which is why this
  needs its own row rather than resting on the existing `head_sequence.py` row.
  It does not reach the gateway wire format: the block is engine-internal
  diagnostics.
- `test_head_gate_v3_replay.py` asserts today that an unlabelled block means
  v2-slow ran. That assertion would have to invert to "every block is labelled".
  It is a test, not protected, and inverting it is the point of the change.

Stopping here as instructed. Nothing was edited against this row.
