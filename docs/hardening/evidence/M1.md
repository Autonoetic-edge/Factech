## What is implemented

The independent `packages/face-auth` profile now has real Keycloak OIDC/code/PKCE,
signed token validation, fresh introspection, encrypted opaque server sessions,
current ownership/role/grant enforcement, CSRF/origin protection, engine token +
session + service authentication, exact route registration and durable audit.
The previous implementation and its failures remain in
[M1-oidc-http-initial.md](M1-oidc-http-initial.md); its 544-test artifacts are historical.

New `schema.py`, Alembic revision `0001_identity`, and `postgres.py` provide
PostgreSQL actors, resources, login state, sessions, grants, replay tracking,
provider revocation tombstones, append-only audit and a durable logout outbox.
No SQLite/memory fallback or implicit startup migration exists. Atomic callback
consumption has one winner across 20 simultaneous connections. Logout commits
local revocation before provider delivery; the bounded outbox drain uses leases
and retry backoff. Role changes increment epochs and revoke sessions.

`operations.py` rechecks locked actor/session/resource state, current grants,
generation, expiry and consent in the same transaction as mutation and audit.
Network/provider calls and analysis occur outside transactions. Twenty concurrent
nonce users across two repository instances produce exactly one successful claim.
Challenge actor/session/tenant/subject/generation/operation bindings are durable;
frozen HEAD_SEQUENCE values, numeric echoes and inclusive 30-second expiry are
preserved. Nonce failures never invoke analysis. Audit failure at enrollment commit
rolls back the template while keeping the already claimed nonce spent.

Participants can enroll, add, verify, list, consent, revoke and request deletion
only for themselves. Operators, reviewers and administrators receive no authority
to perform participant actions on someone else's behalf, including when roles
are combined. Review metadata/diagnostics and frames require distinct current
tenant/round grants. SQL lists filter scope and expiry before pagination; owner
receipts reveal recording status only. The separate evaluation database contains
encrypted synthetic bytes in these tests, never real captures.

`provision.py` provides an offline audited account/role/grant boundary with random
IDs and exact issuer/sub mappings. It has no participant enrollment/template
management or legacy-identity import function. The
[M1 runbook](../M1_RUNBOOK.md) specifies verified provisioning and a future fresh
self-enrollment round; ownership is never guessed from old tester labels.

The 24 gateway / 11 engine registrations remain documented in
`hardened-routes.json`. The original 19 legacy registrations are unchanged.
Legacy services/UI/SDK/biometric code are not imported or wrapped by the new profile.
Normal operations have no analyzer configured and fail with 503. The opt-in
HTTPS integration fixture uses an explicitly synthetic analyzer; this proves the
authorization/transaction path and does not establish biometric acceptance.
