## What is implemented

**Frozen inference through the Analyzer boundary.** New
`packages/face-auth/src/facetech_auth/inference.py` (`FrozenAnalyzer`) calls the
unchanged engine function `engine/app/main._secure_analysis` for every scan, plus
the same `parse_facescan_bytes`, `cosine_similarity`, `PLACEHOLDER_THRESHOLD`,
`_liveness_summary` and `POLICY_VERSION` the legacy endpoints use. No detection,
PAD, head-sequence, liveness, embedding, match or threshold rule is re-implemented
or edited; the 100-file baseline (all `engine/app/*`, models and browser assets)
is byte-identical. Each decision emits the engine's own JSON trace line
(`engine/app/trace.py`) with the model fingerprint added. The default
`MissingAnalyzer` still fails closed with 503; the synthetic analyzer now exists
only in test fixtures and the explicit `--analyzer synthetic` service flag.

The durable challenge store is the single authority for nonce single-use, expiry
and binding. The already-spent challenge's frozen action, parameters and issue
age are handed to the engine's own verdict path through a per-call record, so the
frozen numeric echo, action and `capture_before_issue` timing checks run unchanged.
The engine's admission bound (one worker, four queued, `BUSY` 503) is enforced
before the nonce is spent, as in the legacy `/v1` order.

**Model-bound normalized templates.** Templates are the engine's normalized 512-D
float32 vectors, stored little-endian and byte-identical (tests compare the
decrypted bytes with the source vector). The template format is
`arcface-512-float32-le/<fingerprint>`, where the fingerprint hashes the verified
on-disk bytes of the detector, recognizer and both PAD models against the pinned
SHA-256 values in `engine/scripts/download_models.py` and
`engine/models/anti_spoof/manifest.json`, plus the frozen model/policy labels,
dimension and threshold. A missing or altered model byte refuses startup. Any
active template whose fingerprint differs from the running analyzer fails the
request with `MODEL_VERSION_MISMATCH` before inference; nothing is reinterpreted.

**Schema revision `0002_durable_templates`** (compatible expansion, re-runnable):
`templates` gains `owner_actor_id`, `model_fingerprint`, `key_version` and
`revoked_at`, backfilled from existing rows; `challenges` gains `consumed_at` and
`operation_id`; new `operations` (idempotency) and `deletion_ledger` tables.
Revision 0001 keeps its exact former shape, so the forward migration test is
genuine. The application refuses any other revision (`ready()`); downgrade refuses.

**Capacity without eviction.** Five active templates per subject and 1,000
subjects per team. The subject limit is checked under the subject row lock at
claim (before inference) and again at commit; the team limit (enrolled subjects
at first enrollment, and active subjects at provisioning) is checked under a
tenant advisory lock taken after the actor/session/subject locks. Both return
`CAPACITY_EXCEEDED` 409. The legacy silent oldest-user eviction has no equivalent.

**Atomic operations and idempotency.** Every scan needs an `Idempotency-Key`
header (16–128 URL-safe characters), forwarded by the gateway. One short
transaction guards actor/session/subject/consent, claims the `(actor, key)`
operation with the request digest and spends the nonce by a conditional
`UPDATE ... RETURNING` whose row count is the race decision. Analysis runs
outside any transaction. After provider revalidation, the commit transaction
re-locks and rechecks authority, consent revision, operation state and capacity,
then inserts the template, stores the sanitized result and audits atomically.
Same key + same digest returns the saved outcome marked `replayed` after current
checks; a different digest is `IDEMPOTENCY_CONFLICT`; an unfinished operation is
`OPERATION_IN_PROGRESS`, becoming `OPERATION_INTERRUPTED` after a 120-second
lease; a spent nonce with a new key is `CHALLENGE_INVALID`. Frozen pipeline
rejections (for example `NO_FACE`, `LIVENESS_FAIL`, `MALFORMED_SCAN`) are stored
as the operation's completed outcome and replayed without new inference.

**Revocation** increments the subject generation, sets `revoked_at`, writes
`deletion_ledger` entries and fails in-flight operations for that subject; an
enrollment or verification that was mid-analysis cannot commit. Verification of a
subject without active templates is `USER_NOT_FOUND` before the nonce is read,
preserving the frozen order.

**Recovery.** `postgres.recover()` quarantines a restored database: revokes all
sessions, spends all nonces, fails processing operations and re-applies an
externally supplied deletion ledger so an older backup cannot resurrect a
revoked template or deleted capture.
